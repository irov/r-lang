# Локальные имена и значимость результатов

Дата: 20 сентября 2026. Принятый объём L7 реализован и проверен.

## Подтверждённое решение

Владелец подтвердил: безусловное повторное присваивание локальной переменной
запрещено даже после использования прежнего значения. Для нового значения следует
объявить новую переменную. Цель — упростить видимость и использование переменных.

```r
i32 first = calculate();
print(first);
i32 second = calculate();
print(second);
```

## Границы правила

Простое `=` не может безусловно заменять инициализированную локальную переменную
или параметр. Обычный вложенный блок, `unsafe`, `try` и `finally` не дают разрешения
на замену. Чтение, передача или явное `as void` прежнего значения не снимают запрета.

Условные ветви, тела циклов и catch допускают изменение переменной из внешней
области. Для переменной, объявленной внутри такой ветви или тела, проверка начинается
с её собственного объявления: дополнительного разрешения от внешнего условия нет.
Константное условие `if` и compile-time выбор не служат обходом запрета.

Сохраняются отдельные операции языка: составное присваивание и инкремент, запись
в поле/элемент или через указатель, инициализация `out`, публикация результата `out`
и повторная инициализация после Move/drop. Это правило именования локальных
значений; `const` продолжает отдельно запрещать изменение объекта через все пути.

## Использование полученного результата

Для сохранённого результата вызова проверяется каждое успешное получение, а не
факт чтения переменной когда-либо. Все достижимые пути обычного завершения должны
использовать результат до его потери. Учитываются ветвления, циклы, checked errors
и `finally`.

Владелец отдельно подтвердил: ошибка во время выполнения может прервать работу до
использования результата. Автоматическое освобождение при таком выходе допустимо;
оно не требует искусственного чтения или явного отбрасывания. То же относится к
panic и отмене задачи. Это исключение из обязанности использования, а не новая
гарантия раскрутки стека при panic. Если ошибка перехвачена внутри области переменной и её
хранилище остаётся живым, обычные правила последующего использования сохраняются.

- Обычный результат, результат `await` и значение `@must_use` значимы.
- Чтение, заимствование, передача, Move, явный drop и `as void` подтверждают использование.
- Неявный drop при обычном выходе из области не подтверждает использование.
  На пути ошибки, уничтожающем эту область, дополнительного использования не требуется.
- `@discardable` разрешает отбросить результат непосредственно при именованном вызове.
  Сохранение результата в именованной локальной переменной сохраняет обязанность его
  использования, как предусмотрено действующим R-FUNC-0021.
- Неудачный вызов не создаёт результат; его исключительный путь не требует прочитать
  ещё не созданное значение.
- Чтение или передача значения завершает обязанность; отслеживание произвольных
  последующих копий как линейных ресурсов не вводится.

Изменение этой политики требует обновить примеры, в которых раньше результаты
сохранялись только для проверки типов и затем не использовались. В таких проверках
отбрасывание должно быть явным; проверки владения и ошибок сохраняют свой предмет.

## Обычный ранний выход

Владелец подтвердил: исключение касается только ошибки, panic и отмены.
Обычный ранний выход из runtime-ветви не освобождает от использования результата:

```r
i32 value = calculate();
if (skip == true) { return 0; }
return value;
```

Этот код ошибочен: путь `return 0` не использует `value`. Следует вычислять
результат после раннего выхода либо явно учитывать его на обоих путях.
Правило запрета безусловного повторного присваивания остаётся подтверждённым.
