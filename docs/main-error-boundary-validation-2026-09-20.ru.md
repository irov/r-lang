# Неявные ошибки main: реализация и проверка

Дата: 20 сентября 2026. Таргет: `arm64-apple-darwin`, профиль `hosted-native-async`.

## Контракт

- Core draft.50, Library draft.19; RU/EN обновлены синхронно.
- Сохранены четыре формы `i32 main`: sync/async, с аргументами/без аргументов.
- Неявный набор — ровно 25 Copy-семейств из R-FUNC-0008. Явное `throws` запрещено.
- Пользовательские ошибки, `std.json::error` и четыре владеющих семейства
  `new_error`/`push_error`/`insert_error` по-прежнему требуют обработки.
- Выбран зарезервированный диапазон; новая форма `void main` не вводится.

| Статус | Назначение |
|---|---|
| 0…111 | Статусы приложения |
| 112 | allocation |
| 113 | io, filesystem |
| 114 | network |
| 115 | conversion, format |
| 116 | async_runtime, threading |
| 117 | math, time, environment, process, bytes, string, c_abi |
| 118…123 | Резерв подложки |
| 124 | invalid_main_status |
| 125…127 | Существующие ошибки запуска |

Проверка результата `main` выполняется до платформенного сужения статуса: отрицательное
число или число больше 111 даёт диагностику и статус 124 с обычной очисткой.
Само неявное `throws` ослабляет ограничения; разделение статусов отдельно сужает
допустимые результаты приложения. Все примеры сохраняют поведение и коды возврата.

## Генерация и завершение

Компилятор использует закрытый список `compiler/semantic/main_errors.def` и генерирует
в точке входа C17 отдельную ветку для каждого типа. Поля ошибки проецируются в
`std.error::error` без вызова аллоцирующего `diagnostic()`. Имя берётся из
`std.error::name()`, вывод идёт в существующий emergency sink. Формат содержит
`domain`, `name`, `code`, `native_code`, включая корректную печать `INT64_MIN`.

Все разрешённые payload имеют семантику Copy: у них нет пользовательского Drop.
Carrier потребляется один раз; неизвестный tag или неверное представление домена
остаётся внутренней проверкой целостности, отдельного статуса для него нет.

Порядок: диагностика → запрос отмены и drain → TLS начального потока → static-объекты
→ окончательное завершение runtime. Между объектами также выполняется drain.
Runtime учитывает подготовку задач, их выполнение, обработчики отмены, очистку,
R-потоки и подключённые C-потоки. Сервисы остаются доступны деструкторам.
Синхронный обратный вызов R → C → R из деструктора сохраняет TLS исходного R-потока.

## Проверяемые сценарии

- 124 семантических случая: 25 разрешённых и 6 исключённых семейств для каждой
  из четырёх форм `main`; исключения проверяются по `R-DIAG-EFFECT-001`.
- 36 новых программ кодогенерации: все 15 доменов, конкретные typed errors,
  checked-ошибка через await, границы пользовательских статусов и очистка.
  Для каждой программы проверяются native execution и формат генерируемого C.
- Cleanup-фикстура проверяет диагностику до отмены, подтверждение отмены и Drop
  pending-задачи до TLS/static, ровно однократную деструкцию, а также drain задач
  и R-потоков, созданных каждым деструктором. Процесс выходит со статусом 113
  только после этих проверок.
- При аварийной диагностике включён отказ на первой аллокации через R allocator;
  счётчик попыток остаётся нулевым. Путь форматирования использует стек и `write`.
- Отдельная проверка воспроизвела преждевременную очистку TLS при обратном вызове
  из C; исправление проверено обычной сборкой и ASan/UBSan.
- Все файлы `examples/`, включая `coverage.json`, побайтово совпадают со снимком
  до изменений. Неявные effect-разрешения не считаются использованием API примером.
- Внутренний regex-драйвер тестов переведён на кодирование результатов в 0…111.
  В 16 непустых парах benchmark R/C итоговая контрольная сумма одинаково берётся
  по модулю 109 вместо 251; вычисляемые циклы сохранены. Это сохраняет сравнение
  R/C внутри допустимого диапазона приложения.

`/tmp/r-main-errors-supplemental.log`, `/tmp/r-main-errors-asan{,2}.log`.


## Граница доказательства

Проверки выполняются на текущем Darwin ARM64. ASan/UBSan покрывают выбранные
семантические, codegen и runtime-сценарии; это не полный sanitizer-прогон всей
библиотеки. Аудит реализации проверяет 75 сценариев принятия R → C17; он сам
не компилирует и не запускает сгенерированный C — это делают native CTest-фикстуры.
