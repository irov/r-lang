# R: `out`, вариант A

Дата: 19 сентября 2026. Checkout R, ветка `main`.
Решение владельца: «делаем А» — публикация выходов только при успехе.
Этап: L7.3–L7.5 [плана языка](language-completeness-roadmap.ru.md).

## Реализованный контракт

```r
void split(out i32 left, out i32 right) {
    left = 20;
    right = 22;
}

i32 total() {
    i32 left = 0;
    i32 right = 0;
    split(out left, out right);
    return left + right;
}
```

- `out T name` — отдельный режим параметра; `out place` — явный аргумент.
  Обычный mutable borrow не получает этот контракт.
- Каждый выход начинается как частное неинициализированное значение. Чтение и
  проекции до инициализации целого значения запрещены. На каждом успешном возврате,
  включая конец void-тела, все выходы должны быть инициализированы.
- Публикация происходит после активных `finally`. При замене уничтожается старое
  значение назначения; Copy/Move следуют существующим правилам R.
- При checked error частично или полностью созданные выходы уничтожаются, а старые
  назначения вызывающей стороны сохраняются. Адреса назначений вычисляются один раз,
  в порядке аргументов. Перекрывающиеся выходы и конфликтующие входы отвергаются.
- Каждый успешный выход в локальное хранилище отдельно проверяется на использование
  до перезаписи и выхода из области, включая ветвления, циклы, catch и finally.
  Чтение, передача дальше, явное уничтожение и `as void` подтверждают использование;
  неявное уничтожение не подтверждает его. Неудачный вызов не создаёт нового
  обязательства и не снимает обязательство прежнего результата.
- `@discardable` разрешён и на void-функции с выходами. При именованном вызове он
  разрешает их игнорировать, но не отменяет `@must_use` типа выхода. Разрешение не
  переносится через callable/function item/opaque.
- Режим сохраняется в перегрузках, generics, closures, callable constraints,
  function items, opaque, traits и межмодульном интерфейсе. Интерфейс и C17
  воспроизводимы при перестановке исходных модулей.

Реализация проходит parser → semantic → HIR/MIR → C17. Внутренние выходные слоты
не считаются инициализированными R-значениями до присваивания. Cleanup и проверки
ресурсных контрактов учитывают частные значения и заменяемые назначения.

## Проверки

В `tests/semantic_tests.c` добавлено **66** положительных и отрицательных случаев `out`.
В `tests/fixtures/codegen_out.r` исполняются следующие взаимодействия:

- несколько Copy/Move-выходов и одновременный обычный возвращаемый Move-результат;
- ошибка после первого и после обоих инициализированных выходов;
- возврат через `finally`, инициализация только в `finally`, обработанная внутри
  finalizer ошибка, явное уничтожение выхода в `finally` исключительного пути;

  уничтожаются ровно один раз;

## Спецификация и границы

- Core EN/RU: **0.1.0-draft.48**, новый стабильный **R-FUNC-0022**; interface schema **16**.
  Library остаётся draft.18. Grammar: 276 productions; Core: 474 rules; Library: 236 rules.
- Поддержаны синхронные функции R и полные изменяемые inhabited `unborrowed` значения.
  Async/C-параметры, variadic-выходы и borrowed payload `out` пока отклоняются.
  Синхронный вызов функции с `out` из async-тела подчиняется обычным правилам тела.
- Общий запрет выхода checked error из `finally` сохраняется. Обрабатываемая внутри
  него ошибка допустима. `out` не откатывает I/O и другие внешние эффекты и не меняет
  действующий контракт паники.
- Анализ использования консервативен: корреляции независимых условий и равенство
  runtime-индексов не доказываются. Чтение или явное отбрасывание содержащего объекта
  подтверждает использование его выходов.
- Чтение/forwarding подтверждает использование; обязательство не переносится по
  произвольным копиям как линейный протокол. Общий учёт каждой версии обычного
  возвращаемого результата остаётся в L7.1–L7.2. Весь L7 и весь план не объявлены готовыми.
- Нет новой приёмки TSan, fuzz, Linux или всех target/profile. `conformance_claim=false`.
  Commit и push не выполнялись.
