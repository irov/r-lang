# L7: использование результатов и локальные присваивания

Дата: 20 сентября 2026. Реализация принятого объёма L7 проверена.

## Реализованный контракт

Core — `0.1.0-draft.49`, interface schema — 16, Library — draft.18.
Core содержит 475 правил; Library — 236; EBNF — 276 продукций.

- Обычный сохранённый результат вызова, результат `await`, значение `@must_use`
  и выход `out` проверяются по отдельным получениям и путям выполнения.
  Использование следующего значения не оправдывает потерю предыдущего.
- Обычный `return`, `break` и `continue` не снимают обязательство. Исключительное
  уничтожение области, panic и отмена не требуют искусственного использования.
  Перехваченная внутри живой области ошибка сохраняет обязательство.
- Учитываются короткое замыкание `&&`/`||`, отрицание условия, циклы и `finally`.
  Ожидание использует задачу, а сохранённый результат ожидания проверяется отдельно.
- Безусловный простой `=` для инициализированного целого локального значения или
  параметра даёт `R-DIAG-USE-002` / `R-INIT-0014`, даже после чтения старого значения.
  Runtime-ветвь допускает обновление внешней переменной; вложенный обычный блок,
  `unsafe`, `try`, `finally` и константный `if` такого разрешения не дают.
- Составные обновления, записи в поля/элементы, записи через указатели и повторная
  инициализация после Move/drop сохраняются. Источник второго присваивания частному
  `out` подчиняется общему правилу; публикация выхода остаётся отдельной операцией.
- `@discardable` разрешает игнорировать результат непосредственно при именованном
  вызове. Если результат сохранён в именованной переменной, его использование
  проверяется. Само наличие optional-типа не разрешает молчаливое отбрасывание.

Нормативные тексты EN/RU, Markdown-копии, rule inventory, target manifests и
сгенерированные ABI-отпечатки синхронизированы. Схема интерфейса не менялась.

## Проверки и миграция

именно пример владельца с ранним `return 0`, условная потеря старого значения,
выходы из циклов, checked errors, живой binding после catch, `finally`, `out`,
generic definitions, задачи и сохранённые результаты `@discardable`.

Примеры, R-часть стандартной библиотеки, бенчмарки и тестовые программы приведены
к новому контракту. Последовательные результаты получают новые имена; изменяемое
состояние сценариев хранится в полях. Намеренно неиспользуемые результаты тестовых

локальную тестовую ошибку с сохранением прежних кодов завершения. Проверки

## Границы

Анализ консервативен: корреляции независимых runtime-условий не доказываются.
Чтение, borrow, Move, forwarding и явное уничтожение подтверждают использование;
это не линейный протокол, отслеживающий произвольные последующие копии и обёртки.
Изменение компонента использует обычный агрегат как хранилище. Panic сохраняет
прежний контракт завершения; новая гарантия раскрутки стека при panic не вводится.

Ограничения `out` A сохраняются: синхронные R-функции и unborrowed payload;
async/C-параметры `out` в этот пакет не входят. L8, L4, L5, L9 и итоговая L6
остаются следующими этапами. TSan, fuzz, Linux и все target/profile заново
не принимались; `conformance_claim=false`. Commit и push не выполнялись.
