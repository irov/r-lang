# Scientific calculator

A command-line calculator for every real and complex operation in `std.math`.
Arguments determine the operation and concrete numeric type; computed values go to stdout.
Usage errors return 64 and numeric errors return 65. Output errors of `std.console`,
allocation and task-start failures reach the implicit `main` error boundary (113, 112 and
116). No operands are silently ignored.

Build and run from the repository root:

```sh
cmake -S . -B build-debug -DCMAKE_BUILD_TYPE=Debug
cmake --build build-debug -j8
ctest --test-dir build-debug -R example_calculator --output-on-failure
build-debug/tests/codegen_example_calculator sqrt f64 9
build-debug/tests/codegen_example_calculator hypot f32 3 4
build-debug/tests/codegen_example_calculator mul complex_f64 1 2 3 4
build-debug/tests/codegen_example_calculator split_binary c_long_double 12
```

The results are `3`, `5`, `-5 10`, and `0.75 4`, respectively. Complex operands are
pairs of real and imaginary components. `split_fraction` prints whole and fractional
parts; `split_binary` prints significand and exponent. Angles are in radians.

Types: `f32`, `f64`, `c_float`, `c_double`, `c_long_double`, `complex_f32`, `complex_f64`.
[operations.r](src/operations.r) lists command names. Each typed dispatcher contains
only operations valid for that type; an unsupported combination is a usage error.

[src/main.r](src/main.r) handles command parsing, checked errors and output. `main` hands every
word after the program name to `calculate` as one spread of a range, and `calculate` takes them
as a variadic parameter of runtime strings (Core R-FUNC-0018):

```r
response.result = calculate(...arguments[1..]);

protected std.string::string calculate(str... words) throws ... {
    throw (len(words) < 2usize) Usage { .message = "usage: calculator OP TYPE OPERANDS..." };
    ...
    const str[] operands = words[2..];
```

Two `match` expressions select the work: the operation name through `core::enum_from_name`, with
a `throw` arm for an unknown name, and the type name through
`std.text::ignore_ascii_case(words[1])`, whose string labels compare without ASCII case. The
operands travel on as a spread:

```r
return match (selector) {
    case "f32": example.calculator.number_f32::evaluate(operation, ...operands);
    ...
    default: throw Usage { .message = "unknown number type" };
};
```

Each numeric module parses operands in its exact type, invokes the matching public function,
and formats its result. Native `c_long_double` values never pass through `f64`. The ordinary module map
links these modules; the result goes to standard output through `std.console::print`.

The repetitive typed dispatch is generated by `tools/generate_calculator.py` from the
normative signatures. Generated R files are checked in and readable; a normal build does
not generate or download code. Update them with `python3 tools/generate_calculator.py`.

## Expressions with bounded nesting

`calculator eval EXPRESSION` evaluates `f64` arithmetic with `+`, `-`, `*`, `/`, unary minus
and parentheses:

```sh
build-debug/tests/codegen_example_calculator eval "2 * (3 + 4)"
build-debug/tests/codegen_example_calculator eval "-(1.5 - 4) / 2"
```

The results are `14` and `1.25`. [src/expression.r](src/expression.r) is a recursive descent
parser: `sum` calls `product`, `product` calls `factor`, and `factor` calls `sum` again for a
parenthesized expression, so the nesting of the input decides the depth of the recursion. A
call cycle is permitted only when each of its functions carries `@recursion` (Core
R-FUNC-0026), and each one declares the error that the bound throws:

```r
@recursion(depth = 16)
protected f64 factor(const u8[] text, usize* at) throws Syntax, core::recursion_error {
```

Fifteen levels of parentheses evaluate. At the sixteenth the call that would begin
activation 17 of `sum` throws `core::recursion_error` before its body runs, every activation
below it ends, and `main` reports `expression nests deeper than 16 levels` with status 65. So
does an input of five thousand parentheses: it never reaches the end of the stack. The stack
bound that the compiler derives for the entry counts 16 frames of each of the three functions;
the `!r.stack.frames` metadata of `r-front --emit=llvm-ir` records it with the depth of each
function it counts.
A misplaced byte is `syntax error at byte N`, also with status 65.

## Postfix expressions and a state machine

`calculator rpn EXPRESSION` evaluates reverse Polish notation, such as `3 4 + 2 *` (14), with at
most 16 pending numbers. `postfix` in [src/expression.r](src/expression.r) reads it with a state
machine whose state is the class of the byte at the position, written as a labeled switch:

```r
scan: switch (classify(text, at)) {
case Byte::space:
    at += 1usize;
    continue scan (classify(text, at));
case Byte::digit:
    ...
case Byte::end:
    break;
}
```

`continue scan (value);` selects the clause for the next state without a separate loop and
selector variable, and a clause that completes, such as the one for the end of the text, leaves
the switch (Core R-STMT-0024). An operator without two numbers below it, a number beyond the
sixteenth, a byte that is neither a digit, an operator nor a space, and a text that leaves other
than one number are `syntax error at byte N` with status 65.

`tests/run_calculator_examples.py` invokes every concrete command and compares printed
results with independent Python `math`/`cmath` calculations. It also checks invalid input,
domain and pole errors, the expressions and their nesting limit, and that the measured stack
header counts 16 frames of each parser function. These checks live outside the application.
